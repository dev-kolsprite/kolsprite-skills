# TikTok Growth Plan Workflow

## 1. Confirm the decision inputs

Required for an evidence-backed plan:

1. canonical public TikTok account profile URL;
2. target category or specific product direction;
3. target country/region;
4. primary business goal, such as validating entry, generating Shop sales, building content assets, or recruiting creators.

Ask only for the first missing input that materially blocks the plan. If the user cannot provide it but asks to continue, list the gap and affected decisions, avoid dependent live research, and provide only reversible conditional actions with C confidence.

Record optional budget, team capacity, inventory, fulfillment, available time, price band, language, plan length, and benchmark accounts as user-supplied constraints. Unknown values remain unknown.

## 2. Run and preserve the account audit

Use `tiktok-account-audit` and retain its normalized identity, scope, source ledger, confidence, account type, content pillars/cadence, representative videos, visible commerce evidence, reusable patterns/assets, main constraints, and missing evidence.

Do not upgrade user self-description into measured account evidence or reconstruct private historical operations.

## 3. Run and preserve category/opportunity research

Use the relevant references under `tiktok-shop-growth-research`:

- `opportunity-scan.md` for category/product demand and competition;
- `winning-content.md` when content patterns affect the plan;
- `creator-partnership.md` when creator supply affects the plan;
- `cold-start.md` when a new SKU or first test is central.

Retain the normalized category/market, queries, samples, product/shop/video/creator evidence, opportunity label, content/creator hypotheses, business conditions, policy/compliance checks, confidence, and gaps. Do not replace source observations with a synthetic score.

## 4. Align evidence before comparison

Keep datasets separate when market, category mapping, period, currency, sample selection, field definition, or source is incompatible. Preserve each upstream ledger and reference it in the plan.

An account-category fit decision needs evidence on both sides. A missing side becomes “unable to determine,” not negative fit.

## 5. Build the gap matrix

| Dimension | Current account asset/capability | Category requirement/opportunity | Evidence and fit | Gap/risk | Action impact |
|---|---|---|---|---|---|
| Audience and situation | | | | | |
| Positioning and value promise | | | | | |
| Product/price/inventory/fulfillment | | | | | |
| Content pillars, Hook, and proof | | | | | |
| Creator/content-production capacity | | | | | |
| Market, policy, and asset rights | | | | | |
| Budget, team, and time | | | | | |
| Goal and measurement readiness | | | | | |

Mark each dimension as reusable asset, capability gap, blocking risk, or test needed. Do not give unconditional entry when product access, inventory/fulfillment, or decision-changing evidence remains unresolved.

## 6. Decide retain, pause/stop, and add

- **Retain**: an existing audience insight, positioning element, content formula, product/creator relationship, or operating asset supported by the target opportunity.
- **Pause/stop**: an action that conflicts with the new positioning, lacks measurement, consumes a blocking resource, violates a verified constraint, or has compatible evidence of weak fit. Use “pause for validation” when causality is unknown.
- **Add**: the smallest experiment, evidence asset, product validation, creator test, or compliance check required to close a named gap.

Each decision names its evidence, dependency, metric, review point, and reversal/stop condition.

## 7. Plan three growth paths

### Product path

Match observed category products, price/use case, buyer need, and proof requirements with the account's positioning plus the user's inventory, margin, fulfillment, and compliance constraints.

### Video/content path

Turn reusable account assets plus category-supported Hook, demonstration, proof, objection, and CTA patterns into a limited experiment matrix. Keep caption-derived and visual-review evidence distinct.

### Creator path

Define creator roles and a first cohort from verified category relevance, performance, scale, and contactability. Do not claim exact product history without an ID-confirmed relationship or promise collaboration results.

Prioritize paths according to the primary business goal, evidence strength, and resource constraints.

## 8. Build the 30-day experiment rhythm

- **Day 1–7 — Evidence and readiness:** close blocking product/compliance/tracking gaps; prepare briefs and baseline.
- **Day 8–14 — First test:** launch a bounded set of product/content/creator hypotheses.
- **Day 15–21 — Repeat or revise:** compare compatible evidence, repeat the strongest signal, and change one meaningful variable at a time.
- **Day 22–30 — Focus or stop:** concentrate resources on validated paths or stop/pause unsupported ones.

Treat content, SKU, and creator quantities as proposed test volume unless the user's team capacity supports them. Every phase needs an owner/input, observable metric, review decision, and scale/adjust/stop condition.

## 9. Define compatible metrics

Select a small KPI set that matches the business goal. Preserve source, period, population, currency, and definition for views, engagement, clicks, product actions, units, GMV, cost, or pipeline metrics. Do not substitute one for another or estimate ROI without compatible revenue and cost.

## 10. Stop conditions

Stop or downgrade the plan when an upstream identity cannot be confirmed, category/market is unresolved, datasets cannot be aligned, public access is restricted, insufficient-points/rate-limit/authentication/tool errors block a required chain, or a product/compliance/economic condition remains decision-changing.

Report what is complete, unresolved decisions, confidence, and the smallest useful next input. Never fill the gap with assumed best practices or guaranteed outcomes.
