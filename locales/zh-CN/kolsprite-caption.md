# TikTok 字幕与脚本分析

收到 TikTok 视频内容处理请求后，通过当前兼容连接访问 `caption_extract_url`；它既可能直接暴露，也可能位于云雅门面后的内部目录。无需再询问用户是否使用 MCP。

## 兼容 MCP 路由

- SellerSpace 云雅统一 MCP 可用且已鉴权时，优先使用云雅。
- 支持业务工具直接调用，以及云雅当前版和旧版两种门面入口。
- 直接模式下，按语义业务名称识别并调用 `caption_extract_url`。
- 云雅门面模式下，如果宿主顶层看不到业务工具，最多进行一次宿主级发现，并优先使用产品专属入口 `yunya_search_kolsprite_tools`。用 TikTok 字幕提取意图查询一次；取得真实内部工具名及完整输入 Schema 后，再通过 `call_read_tool` 调用。
- 如果产品专属入口不可用、但可发现旧版通用入口 `yunya__search_tools`，则使用 provider `kolsprite`、operation `read` 和相同字幕意图调用一次。产品专属入口可用时，不应优先使用通用入口。
- 不得猜测门面命名空间、内部工具名、包装结构或参数；本次任务复用已发现的名称和 Schema。
- 宿主顶层没有命中 `caption_extract_url`，不代表内部业务工具不存在。只有直接模式以及可用的当前版或旧版门面查询都失败后，才能报告业务依赖缺失。两个门面入口都无法发现时，应明确报告连接器发现失败，不得切换到飞书妙记或其他无关替代服务。
- 独立 KOLSprite MCP 仅在所需语义工具名、输入结构和返回结构一致时兼容。
- 如果两种连接同时启用，本次任务全程只使用一个连接，优先云雅，不得在两个服务之间重复执行付费调用。
- 如果缺少 `caption_extract_url` 或其结构不兼容，应报告依赖缺失，不得替换为其他字幕工具名。

## 必需输入

工具需要 TikTok 视频 URL。缺少时只询问视频链接。只有市场或 URL 上下文支持时才启用东南亚选项。

## 执行方式

1. 先提取字幕或口播文本，再进行分析。
2. 返回结果包含时，保留原始顺序、时间戳和语言。
3. 翻译时明确区分原始字幕和译文。
4. 分析脚本时，每个 Hook、卖点、证明点、异议处理和 CTA 都必须以返回文本为依据。
5. 对比多个视频时，应分别提取，并清晰保留各视频的来源边界。

## 点数控制

- 每次字幕操作的点数可能与数据搜索工具不同；选择本 Skill 本身不代表发生扣费。
- 只提取用户提供或与决策直接相关的视频。批量处理时说明请求数量，点数不足后停止其余调用。
- 不得写死或估算点数价格。只有 MCP 或宿主客户端返回实际扣费或余额时才能报告。
- 如果要超出用户指定的视频范围，或仅为改变展示格式而重新提取未变化的 URL，应先询问用户；已有字幕仍有效时应直接复用。

## 能力边界

- 不得补写或编造缺失的口播。
- 没有返回字幕时应明确说明。
- 除非返回文本明确提到，否则字幕数据不能说明画面演示、屏幕文字、剪辑、音乐、构图或商品外观；该限制影响用户所需结论时必须说明。
- 没有表现数据支持时，不得声称某个脚本元素导致了视频表现。
- 如果多视频内容策略或可供达人拍摄的 Brief 还需要当前商品或视频指标，应在完成用户要求的字幕提取后，把决策流程交给 `tiktok-shop-growth-research`。
- 当前 URL 格式被拒绝或字幕结果不明原因为空时，查阅带日期的[已知问题记录](../tiktok-shop-growth-research/references/known-issues.md)。保留实际错误，并只根据记录选择一次安全重试；不得把历史兼容情况当作当前保证。
