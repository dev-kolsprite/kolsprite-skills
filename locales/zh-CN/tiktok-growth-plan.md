# TikTok 增长计划

将账号诊断与类目或机会研究整合成一份可执行计划。不得重复获取或暗中重新解释上游证据。

## 兼容 MCP 路由

- 使用一个能够提供兼容 KOLSprite 语义工具契约的有效连接；SellerSpace 云雅统一 MCP 可用且已鉴权时优先使用。
- 支持业务工具直接调用，以及云雅当前版和旧版两种门面入口。
- 直接模式下，按语义业务名称识别所需证据工具。
- 云雅门面模式下，如果宿主顶层看不到业务工具，最多进行一次宿主级发现，并优先使用产品专属入口 `yunya_search_kolsprite_tools`。查询最小决策相关工具集合；使用返回的真实内部工具名及完整输入 Schema，再通过 `call_read_tool` 调用。
- 如果产品专属入口不可用、但可发现旧版通用入口 `yunya__search_tools`，则使用 provider `kolsprite`、operation `read` 和相同查询调用。产品专属入口可用时，不应优先使用通用入口。
- 不得猜测门面命名空间、内部工具名、包装结构或参数；本次任务复用已发现的名称、Schema 和上游证据。
- 宿主顶层没有命中业务工具，不代表内部工具不存在。只有直接模式以及可用的当前版或旧版门面查询都失败后，才能报告业务依赖缺失。两个门面入口都无法发现时，应明确报告连接器发现失败，只保留边界清晰的部分计划，不得切换到无关替代品。
- 独立 KOLSprite MCP 仅在所需工具名、输入结构和返回结构一致时兼容。
- 如果两种连接同时启用，本次任务的全部 MCP 证据调用都使用云雅，不得跨服务重复执行付费调用。
- 缺少必要工具或工具结构不兼容时，将其视为证据缺口，保留有边界的部分计划，不得静默切换契约。

## 输入检查

可用于决策的计划需要公开账号主页 URL、目标类目或商品、目标市场和主要业务目标。缺少的信息会改变定位、市场证据、KPI 或优先级时，只询问优先级最高的一项。用户无法提供但仍希望继续时，应给出有条件的部分框架，并将没有证据支持的决策标为待解决。

预算、团队能力、库存、履约、每日可投入时间、内容语言、价格带和基准均为可选约束。不得把缺失约束转化为行业基准。

## 交付内容

1. 对齐上游来源、时间、市场、类目、对象 ID、单位和证据置信度。
2. 建立“账号能力 × 类目机会”差距矩阵。
3. 决定保留、暂停或停止以及新增哪些动作。
4. 根据业务目标和证据，对商品、视频或内容和达人路径排序。
5. 制定第 1–7 天、8–14 天、15–21 天和 22–30 天的测试与复盘计划。
6. 为每项行动明确依赖、负责人或所需输入、可观察指标、复盘点，以及扩大、调整或停止条件。

进行任何新的 MCP 调用前，先复用已经完成的上游诊断或研究证据。不同工具可能消耗不同点数，Skill 编排本身不代表发生扣费。不得写死价格、在没有决策必要性时增加调用，或在点数不足后继续。只有 MCP 或宿主返回实际用量时才能报告。

不得承诺增长、编造最佳发布量，也不得执行发布、发送消息、下单、修改店铺或投放广告。
