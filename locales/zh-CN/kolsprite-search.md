# TikTok 数据搜索

将直接的 TikTok 数据请求路由到当前已连接且符合 KOLSprite 工具契约的最小必要调用。自动使用 MCP，无需询问用户是否调用。

## 兼容 MCP 路由

- SellerSpace 云雅统一 MCP 可用且已鉴权时，优先使用云雅。
- 支持业务工具直接调用，以及云雅当前版和旧版两种门面入口。
- 直接模式下，按语义业务名称识别并调用所需类目、达人、商品、视频或店铺工具。
- 云雅门面模式下，如果宿主顶层看不到所需业务工具，最多进行一次宿主级发现，并优先使用产品专属入口 `yunya_search_kolsprite_tools`。查询本次直接查询所需的最小工具集合；使用返回的真实内部工具名及完整输入 Schema，再通过 `call_read_tool` 调用。
- 如果产品专属入口不可用、但可发现旧版通用入口 `yunya__search_tools`，则使用 provider `kolsprite`、operation `read` 和相同查询调用。产品专属入口可用时，不应优先使用通用入口。
- 不得猜测门面命名空间、内部工具名、包装结构、类目值或参数；整个查询复用已发现的名称和 Schema。
- 宿主顶层没有命中业务工具，不代表它不在内部目录。只有直接模式以及可用的当前版或旧版门面查询都失败后，才能报告依赖缺失。两个门面入口都无法发现时，应明确报告连接器发现失败，不得把无关数据源当作等价替代。
- 独立 KOLSprite MCP 仅在所需语义工具名、输入结构和返回结构一致时兼容。
- 如果两种连接同时启用，本次查询全程只使用一个连接，优先云雅，不得在两个服务之间重复执行付费调用。
- 缺少必要工具或其结构不兼容时，应报告依赖缺口并缩小或停止查询，不得猜测替代工具。

## 工具路由

- 达人内容类目值解析：用户要求按达人内容类目筛选，且本次任务尚无已验证可用值时，先调用 `creator_category_list`，再调用 `creator_search`。
- 商品类目 ID 解析：需要按类目筛选达人、商品、视频或店铺，且本次任务尚无已验证可用 ID 时，先调用 `product_category_list`。
- 达人身份、粉丝规模、互动、内容类目、带货活动、可联系性或达人候选名单：调用 `creator_search`。
- 商品身份、价格、评分、评论、上架日期、销量、增长、达人数或视频数：调用 `product_search`。
- 带货视频身份、达人、商品、播放、互动、销量、发布时间或时长：调用 `video_search`。
- 店铺身份、类型、类目、评分、商品、销量、达人或视频：调用 `shop_search`。

只有用户的直接查询确实需要关联记录时才使用多个工具。下游工具支持时复用已返回 ID，例如先用 `shop_search`，再以 `shop_id` 调用 `product_search`；或先用 `product_search`，再以 `product_id` 调用 `video_search`。

不得声称 `creator_search` 能识别推广某个特定商品的准确达人。当前公开达人工具支持类目和表现筛选，不支持按商品 ID 查询关系。

## 类目解析

- 把类目列表工具作为参数解析器，而不是面向用户的搜索结果或每次查询必做的预检。无需类目筛选或本次任务已有有效值时跳过。
- 将用户的中英文达人类目表述与 `creator_category_list` 匹配，把返回的 `value` 传给 `creator_search.category_list`。
- 遍历 `product_category_list` 的递归树，匹配 `categoryCn` 或 `categoryEn`，根据需要将返回的完整 `category` 值传给 `product_search.cat_ids`、`shop_search.category`、`video_search.product_category_list` 或 `creator_search.product_category_list`。
- 内容赛道或账号定位解释为达人类目；销售、推广商品或合作方向解释为商品类目。不得仅为回避“美妆达人”之类的歧义而同时设置两种类目筛选；应根据请求上下文判断、说明重要假设，或仅在不同选择会实质改变结果时询问一次。
- 当前搜索结构接受数组，但每次调用只支持一个类目值。选择既保留用户意图又无歧义的最窄匹配。两个可能映射会实质改变结果时询问一次，否则使用更宽的有效父类目并披露。
- 不能把显示名称作为接受值或 ID 传入，不能编造 ID，也不能把实时类目表固化进 Skill 文本。本次任务成功解析一次后复用该映射。解析器不可用或找不到安全匹配时，省略类目筛选；有帮助时使用明确标注范围的关键词查询，并披露限制。
- 使用上述语义工具名。MCP 宿主可能给可调用工具增加客户端或服务端前缀，不得写死某个 Agent 的前缀。

## 查询规则

1. 识别市场、关键词、类目、价格、粉丝、互动、销量、增长、日期、排序和分页大小等明确筛选条件。
2. 可选输入的不同选择不会实质改变答案时使用工具默认值；重要假设必须说明。
3. 只询问既是必填又无法安全推断的信息。
4. 将用户要求的结果数量转换成最小充分分页计划。用户要求“全部”时，使用支持的最大分页大小，持续请求，直到没有下一页、已覆盖请求范围、达到服务限制或错误中断。
5. 使用稳定对象 ID 对分页结果去重，并报告请求数量、页码范围、原始行数、去重后行数和停止原因。
6. 应用用户指定的排序。实时结构未确认服务端排序值时，只能在已披露的采集范围内进行本地排序。
7. 编码百分比增长筛选前，检查实时结构或已验证的官方示例。不得猜测 50% 应表示为 `50` 还是 `0.5`；仍无法确认时省略该筛选并说明限制。
8. 初始查询为空时，如果仍能回答用户意图，可以放宽一个非关键条件或尝试一个相近同义词，并说明放宽内容，不能静默改变范围。
9. 完成用户要求的直接查询或有限对比后停止。决策型后续问题交给 `tiktok-shop-growth-research`。

## 点数控制

- 点数以当前账号规则下实际执行的工具为准；选择本 Skill 本身不代表发生扣费。
- 使用能回答请求的最小调用和分页计划，复用返回记录；没有说明原因时不得重复相同的付费调用。
- 不得写死或估算点数价格。只有当前 MCP 响应或宿主客户端显示扣费或余额时才能报告。
- 点数不足时停止，并标明已完成页数或行数以及剩余工作。超出用户请求范围的额外工具或页面会显著增加点数时，应先询问用户。

## 错误与不完整采集

- 遇到鉴权失败、工具不可用、点数或权限不足、限流或重复服务错误时，停止受影响的调用链。
- 不得通过更换凭证、规避限制或缩小请求以掩盖中断的方式重试点数、权限、限流或鉴权错误。
- 将中断的采集标记为 **不完整**，说明已完成页数或行数、剩余请求工作，以及哪些结论只适用于已采集样本。
- 不得把第一页或被限流的采集称为“全部结果”。
- 当前出现服务错误、结构不匹配、类目结果为空或稳定 ID 页面疑似重复时，查阅带日期的[已知问题记录](../tiktok-shop-growth-research/references/known-issues.md)。它只能作为复测指南，不能证明历史问题当前仍然存在。

## 证据与回答规则

- TikTok 事实只能基于当前 MCP 输出，不得编造缺失记录或指标。
- 来源、市场、筛选、排序、时间口径、页码和返回样本量影响解释时，应明确标注。
- 保留字段实际时间窗口，不得把累计或未注明口径的销量改称 7 天或 30 天销量。
- 区分 MCP 字段与客户端计算。计算比例、排名或集中度时，应展示公式或通俗计算方式。
- 关键词匹配结果在核验商品或类目相关性前只能视为候选。
- 空结果表示“在这些条件下没有返回记录”，不能证明对象或市场不存在。
- 有帮助时使用返回的对象链接，不得编造 TikTok 或 KOLSprite URL。
- 先给结果或候选名单；次要维度只有会改变用户决策时才加入。
- 分析型请求应以一个优先行动、支持证据、观察指标和复盘或停止条件收尾。用户只要求简单查询时，不要附加行动方案。
- 可复用分析任务或面向合作方的示例应采用共享的[任务证据展示规范](../tiktok-shop-growth-research/references/evidence-display.md)，且不得把一次查询执行描述成已发生的客户业务结果。
