# Amazon 商品 TikTok 机会验证

判断用户提供的 Amazon 商品是否有足够证据进入目标市场的小规模 TikTok 测试，并设计最小有效的内容与达人实验。这里判断的是是否进入测试，而不是承诺备货、广告预算或全面上市。

从卖家精灵开始。除非当前对话中已经存在完整且标明来源的 Amazon 证据摘要，否则第一个业务数据工具必须是 `asin_detail`。不得先调用达人精灵业务数据工具。

## 兼容 MCP 路由

- SellerSpace 云雅统一 MCP 可用且已鉴权时优先使用。经验证的统一契约可通过一个连接完整支持本 Skill 的“卖家精灵优先、达人精灵验证”流程。
- 支持业务工具直接调用，以及云雅当前版和旧版两种门面入口。
- 直接模式下，按语义业务名称识别所需卖家精灵或达人精灵工具。
- 云雅门面模式下，如果宿主顶层看不到业务工具，最多进行一次宿主级发现，并优先使用产品专属入口。Amazon 阶段使用 `yunya_search_sellersprite_tools`，再通过 `call_read_tool` 调用返回的真实内部工具。完成或明确降级该阶段后，才能使用 `yunya_search_kolsprite_tools` 获取 TikTok 验证工具。
- 如果所需产品专属入口不可用、但可发现旧版通用入口 `yunya__search_tools`，则使用 provider `sellersprite` 或 `kolsprite`、operation `read` 和相同最小必要查询调用。对应产品专属入口可用时，不应优先使用通用入口。
- 使用所选搜索入口返回的完整输入 Schema，不得猜测门面命名空间、内部工具名、包装结构或参数。尽量一次发现相关工具，并在本次任务中复用名称和 Schema。
- 宿主顶层没有命中 `asin_detail` 或达人精灵业务工具，不代表内部工具不存在。只有直接模式以及可用的当前版或旧版门面查询都失败后，才能报告业务依赖缺失。两个门面入口都无法发现时，应明确报告连接器发现失败，不得切换到无关替代品。
- 兼容的独立卖家精灵 MCP 在已连接、已鉴权，并提供所需语义工具名、输入结构和返回结构时，可以完成 Amazon 阶段。通过独立连接完成整个流程，还需要兼容的达人精灵 MCP。
- 使用云雅时，即使两组能力来自同一个 MCP 连接，也必须保持逻辑上的卖家精灵优先顺序。
- 使用独立连接时，必须完成或明确降级卖家精灵阶段，才能使用另一条达人精灵连接。
- 云雅和独立服务同时存在时，整个流程优先使用云雅，不得跨服务重复执行付费调用。
- 按语义业务名称而不是特定客户端的服务前缀识别工具。缺少必要能力或结构不兼容时，应停止或缩小流程。

## 输入要求

- 一个 Amazon ASIN 或 Listing。
- Amazon 站点和目标 TikTok 市场。能够从 URL 和上下文可靠判断时可以推断，并说明假设；只有歧义会实质改变分析时才询问。
- 可选约束包括价格、库存、目标受众、达人预算、测试周期或已知竞品。

每次只处理一个 ASIN。用户提供多个 ASIN 时，建议先做信号对比，或请用户选择一个进行完整验证。

## 根据意图选择深度

- **快速验证：** 用户询问该商品是否值得探索或测试时默认使用。建立 Amazon 摘要、验证当前 TikTok 证据并给出有边界的判断，不做字幕分析或大范围达人扩展。
- **完整测试方案：** 用户明确询问如何测试、要求内容方向和达人，或要求深入或完整验证时使用。增加达人筛选，只对形成脚本级建议所必需的最小代表性样本进行字幕分析。

所选深度范围内无需每个阶段都停下来询问。只有商品或市场身份存在实质歧义、额外扩展产生请求范围之外的显著成本，或需要外部授权时才暂停。

## 跨平台工具使用

- 按 MCP 声明的业务名称和输入结构匹配工具。宿主可能增加命名空间或延迟暴露工具，不得写死宿主专用前缀。
- 条件允许时根据当前 MCP 元数据核验必要能力。实时元数据优先于本 Skill 的快照。
- 不得猜测凭证、类目 ID、枚举值、请求包装或返回字段名。
- 凭证不得写入 Skill 和输出。
- 使用能够回答决策的最少调用，并复用已返回记录。
- 除非 MCP 或宿主返回实际用量，否则不得报告点数或额度扣减。

## 强制执行顺序

把卖家精灵作为商品理解层，把达人精灵作为后续 TikTok 验证层。

1. 先发现或确认卖家精灵能力，再发现达人精灵能力。不能因为输入包含 ASIN 就先查询达人精灵工具。
2. 除非对话中已经存在完整且标明来源的 Amazon 证据摘要，否则第一个业务数据调用必须是卖家精灵 `asin_detail`。
3. 调用任何达人精灵业务数据工具（包括 `asin_analysis_video`）前，必须完成或明确降级所需的卖家精灵证据阶段。
4. 复用同一对话中已经充分建立的卖家精灵证据，不得仅为满足顺序而重复付费调用。
5. 卖家精灵不可用且用户只提供了 ASIN 时，应在获取达人精灵数据前停止，并请求最少的 Listing 信息。如果用户已提供充分的 Listing 证据，可降低置信度继续，并披露替代关系。

宿主级连接检查不属于业务分析。如果宿主必须预先检查全部 MCP，应尽量静默进行，同时仍保证卖家精灵是第一个用户可见且第一个业务数据阶段。

## 核心流程

1. **标准化商品和市场。** 确认 ASIN、商品形态、核心功能、Amazon 站点、目标 TikTok 市场和市场代码映射。
2. **建立 Amazon 证据摘要。** 使用卖家精灵获取商品身份、当前需求或生命周期证据、近期消费者语言和直接竞品种子；预测值必须标为预测。
3. **把证据转换为假设。** 形成精确商品、使用场景、痛点、演示和竞品查询组。Amazon 事实只能产生假设，不能证明 TikTok 机会。
4. **在 TikTok 验证。** 使用达人精灵采集 ASIN 相关候选、商品和视频。先清理相关性，再计算当前热度、近期方向、内容结构、集中度和达人扩散。只有所选深度需要时才扩展到达人、店铺或字幕工具。
5. **判断五个维度。** 分别评估 Amazon 需求有效性、TikTok 商业信号、最近 30 天动量、内容适配与竞争结构，以及达人扩散和可执行性；决策与证据置信度分开呈现。
6. **证据支持时给出一个判断和一个最小测试。** 使用 `worth_testing`、`conditional_test` 或 `not_recommended`。证据不完整时不得给出业务判断，只报告证据状态和最小下一步获取动作。

## 不可违反的证据规则

- 分开呈现 **已观察 MCP 数据**、**客户端计算**、**业务判断** 和 **建议动作**。
- MCP 候选总数不等于有效相关结果数。
- 将记录分类为 `same_product_family`、`highly_similar`、`related_scene` 或 `noise`，只有前两类进入机会计算。
- 分开处理最近 30 天、前 30 天和累计值。
- 当前滚动 30 天销量字段不是视频发布月份的历史销量。
- 除非工具明确证明身份，否则不得声称某个 TikTok 商品就是该 Amazon ASIN。
- 不得声称 TikTok 导致 Amazon 销量变化、预测未来销量，或把估算值包装成平台官方数据。
- 缺失证据应标为 `unverified`，不等于零，也不自动代表信号弱。

## 降级与停止

- 卖家精灵不可用但用户提供了充分 Listing 内容时，可以使用用户提供的 Amazon 证据并降低置信度继续。只有 ASIN 时，应请求最少的 Listing 信息或停止联合验证。
- 达人精灵不可用时，可返回 Amazon 摘要和验证假设，但不得给出 TikTok 测试建议。
- 缺少直接 ASIN 视频分析时，不得用通用视频搜索替代并声称具有 ASIN 映射。通用搜索只能支持明确标注的商品家族研究。
- 宿主中没有类目列表工具时，省略类目筛选并对返回结果做明确的相关性过滤，绝不能编造类目值。
- 遇到鉴权、权限、点数不足、结构错误或重复服务错误时停止受影响分支，并报告哪些内容仍已验证、哪些没有执行。
- 有效 TikTok 记录少于 3 条时，通常不足以给出可靠信号等级。应展示证据和下一步验证方式，而不是强行下结论。
