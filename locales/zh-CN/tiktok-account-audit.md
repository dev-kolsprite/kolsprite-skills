# TikTok 账号诊断

根据可追溯的公开证据诊断 TikTok 账号，不得把无法访问或缺失的数据当作零。

## 兼容 MCP 路由

- 使用一个能够提供兼容 KOLSprite 语义工具契约的有效连接；SellerSpace 云雅统一 MCP 可用且已鉴权时优先使用。
- 支持业务工具直接调用，以及云雅当前版和旧版两种门面入口。
- 直接模式下，按语义业务名称识别所需增强工具。
- 云雅门面模式下，如果宿主顶层看不到增强工具，最多进行一次宿主级发现，并优先使用产品专属入口 `yunya_search_kolsprite_tools`。查询最小必要增强工具集合；使用返回的真实内部工具名及完整输入 Schema，再通过 `call_read_tool` 调用。
- 如果产品专属入口不可用、但可发现旧版通用入口 `yunya__search_tools`，则使用 provider `kolsprite`、operation `read` 和相同查询调用。产品专属入口可用时，不应优先使用通用入口。
- 不得猜测门面命名空间、内部工具名、包装结构或参数；本次任务复用已发现的名称、Schema 和证据。
- 宿主顶层没有命中增强工具，不代表内部工具不存在。只有直接模式以及可用的当前版或旧版门面查询都失败后，才能将业务工具标为缺失。两个门面入口都无法发现时，应明确报告连接器发现失败，并且只能沿用下文有边界的公开证据路径，不能使用无关替代品。
- 独立 KOLSprite MCP 仅在所需工具名、输入结构和返回结构一致时兼容。
- 如果两种连接同时启用，本次任务的全部 MCP 增强都使用云雅，不得跨服务重复执行付费调用。
- 缺少增强工具或工具结构不兼容时，将其视为证据缺口，并保留下文的公开证据降级路径。

## 执行流程

1. 必须获得公开 TikTok 主页 URL，并按照工作流验证。仅有昵称不足以确认身份。
2. 有可用浏览器时，只读取公开主页和视频页面。遇到登录、验证码、反爬、地区或访问限制时停止。
3. `creator_search` 只能用于增强已经通过官方主页或已验证视频确认的身份。只有返回的 Handle 或达人 ID 完全一致时才接受增强结果。
4. `video_search` 只能作为补充来源，且返回视频的达人身份必须能够交叉确认；不得把关键词结果称为该账号的完整视频列表。
5. 只有口播 Hook、卖点、证明、异议处理或 CTA 会影响判断时，才对少量已验证的代表性视频使用 `caption_extract_url`。
6. 没有浏览器时，如果精确 MCP 匹配以及用户提供的公开截图或导出材料已经足够，可以继续；否则交付有边界的部分诊断，或只询问一个会实质改变诊断的缺失输入。

## 点数控制

- 所有 MCP 增强使用一个兼容服务。点数以实际执行的搜索或字幕工具为准，而不是以选择本 Skill 为准。
- 先确认身份和公开证据，再调用能改变诊断的最少 MCP 增强和代表性字幕样本。有效字幕或上游记录可以复用时，不得重复付费调用。
- 不得写死点数价格。只有 MCP 或宿主返回实际用量时才能报告。点数不足时停止剩余增强，同时保留有边界的部分诊断。

## 输出边界

- 分开呈现公开页面观察、KOLSprite MCP 观察、客户端计算和业务判断。
- 报告请求样本与实际样本、采集窗口、来源清单、缺失字段、停止原因和 A/B/C 置信度。
- 根据重复样本证据区分内容型、带货型、品牌型和混合型账号，不能只看单条视频或粉丝数。
- 区分置顶、近期、高表现、低表现和商业视频。
- 只有重复证据支持时才能描述“运营逻辑”。可复用的启动流程应标为推导方案，而不是对账号私有历史的还原。
- 不得发布内容、发送消息、关注、下单、修改账号、绕过控制，也不得暴露凭证或联系方式。
